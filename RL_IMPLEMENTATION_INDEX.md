### The 15 Camera Movement Types

**Position/Rotation Movements** (6 types):
1. **Pan** - Horizontal rotation (requires direction: left/right)
2. **Tilt** - Vertical rotation (requires direction: up/down)
3. **Roll** - Optical axis rotation (requires direction: clockwise/counterclockwise)
4. **Truck** - Lateral translation (requires direction: left/right)
5. **Crane** - Vertical translation (requires direction: up/down)
6. **Arc** - Orbital movement (requires direction: clockwise/counterclockwise)

**Physical Movements** (3 types):
7. **Dolly In** - Forward movement (no direction)
8. **Dolly Out** - Backward movement (no direction)
9. **Follow** - Subject tracking (no direction)

**Complex/Static** (4 types):
10. **Free Fly** - 3D free-form movement (no direction)
11. **Static** - Fixed camera (no direction)
12. **Unstable** - Jittering/shaking (no direction)
13. **Focus Shift** - Focus plane change (no direction)

**Optical** (2 types):
14. **Zoom In** - Focal length increase (no direction)
15. **Zoom Out** - Focal length decrease (no direction)

### 7 Reward Function Options

| Option | Complexity | Signal Type | Use Case | Recommended |
|--------|-----------|------------|----------|-------------|
| 1. Basic F1 | Simple | Frame-level F1 | MVP, fast iteration | - |
| 2. Per-Label | Medium | Individual label scores | Debug/analysis | - |
| 3. Hierarchical | Medium | Type (70%) + Direction (30%) | Direction sensitivity | - |
| 4. Segment IoU | Medium | Temporal grounding | Fix timing issues | - |
| **5. Composite** | Complex | Multi-signal aggregation | Production | ⭐ **YES** |
| 6. Confidence-Weighted | Medium | Penalize confident errors | Calibration | - |
| 7. Class-Balanced | Medium | Weight rare movements higher | Long-tail coverage | - |

**Recommendation**: Start with **Option 5 (Composite)**
- Combines frame-level F1 (70%), format (15%), confidence (15%)
- Balanced training signal
- Proven approach for multi-label tasks

### F1 Score Computation (Frame-Level)

```
At each 0.1s time point:

GT labels = {movements at that time}  e.g., {"Pan_left", "Dolly_In"}
Pred labels = {predicted movements}   e.g., {"Pan_left"}

TP = |GT ∩ Pred| = 1
FP = |Pred - GT| = 0
FN = |GT - Pred| = 1

Precision = TP/(TP+FP) = 1/1 = 1.0
Recall = TP/(TP+FN) = 1/2 = 0.5
F1 = 2*P*R/(P+R) = 2*1.0*0.5/1.5 = 0.67

✓ PARTIAL CREDIT: F1=0.67, not 0
```

### SFT→RL Best Practices

| Aspect | SFT Phase | RL Phase |
|--------|-----------|----------|
| Data | Full dataset + reference solutions | Same videos, same questions, NO references |
| Model outputs | Fixed (reference) | Generated by model during training |
| Training signal | Cross-entropy loss on reference | Reward signals from evaluation |
| Capabilities | Format, instruction-following | Improve accuracy via RL |
| Format constraint | Native to training | Include in reward function (10-20%) |
| Duration | Baseline | 3-5 epochs |

**Key Point**: ✅ Format and instruction-following are NOT lost in SFT→RL transition
- SFT teaches these capabilities
- GRPO learns to improve within those constraints
- Include format reward to maintain JSON/choice output
